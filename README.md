# Polynom Hunter

Polynom Hunter is an experimental project focused on
discovering polynomial relationships from numerical data.

## Long-Term Goal

The main goal of Polynom Hunter is to develop an efficient algorithm that discovers the simplest polynomial capable of describing a given dataset.

The initial implementation constructs an interpolating polynomial by solving a linear system with an n × n Vandermonde matrix. However, this approach can be computationally expensive and may produce unnecessarily high-degree polynomials.

I want to investigate whether it is possible to:

- Automatically determine the appropriate polynomial degree.
- Avoid constructing large matrices when a simpler polynomial is sufficient.
- Reduce computational time and memory usage.
- Recover simple polynomial relationships from large datasets.

For example, given 1,000 points generated by the function `f(x) = 2x + 1`, the algorithm should ideally recover `P(x) = 2x + 1` rather than construct a polynomial of degree up to 999.

The project will focus on mathematical reasoning, algorithm development, and experimental evaluation.

## Current Version: v0.1.0

The first version implements polynomial interpolation
using linear algebra.

### Implemented

- CSV data loading
- Vandermonde matrix construction
- Custom Gauss-Jordan elimination (RREF)
- Polynomial coefficient calculation

## Mathematical Approach

Given n observations:

D = {(x_1, y_1), ..., (x_n, y_n)}

We construct a polynomial of degree at most n-1
that passes through all observations.

The polynomial coefficients are obtained by
solving a linear system with a Vandermonde matrix.

See [Algorithm Documentation](docs/algorithm.md).

coefficients in descending degree order.

## Limitations

The current implementation has several computational, numerical, and algorithmic limitations.

### 1. Computational Complexity
- **Time complexity:** O(n³), primarily due to Gauss-Jordan elimination.
- **Space complexity:** O(n²), because the algorithm constructs and stores an n × n Vandermonde matrix.
- Processing large datasets can be computationally expensive.

### 2. Numerical Stability
- The algorithm uses Python floating-point arithmetic, which introduces rounding errors.
- A fixed tolerance of 1e-10 may incorrectly classify small nonzero values as zero.

### 3. Polynomial Degree
- The algorithm uses n coefficients for n observations, regardless of the actual complexity of the underlying relationship.
- It cannot automatically determine the minimum sufficient polynomial degree.
- This may lead to unnecessarily complex models.

### 4. Input Validation
- The implementation assumes that all x-coordinates are distinct.
- Invalid, empty, or inconsistent input data is not handled robustly.

### 5. Implementation Efficiency
- The current implementation uses Python lists and explicit loops.
- It does not take advantage of specialized numerical algorithms or optimized linear algebra routines.

These limitations will guide the development and evaluation of future versions of Polynom Hunter.


## Roadmap

### 1. What We Have Accomplished

We developed our first working polynomial interpolation algorithm.

It takes a set of data points, constructs a Vandermonde matrix, and calculates the polynomial coefficients using our own implementation of RREF (Gauss-Jordan elimination).

For n points with distinct x-coordinates, we can construct the unique polynomial of degree at most n-1 that passes through all the given points.

However, this approach has several significant limitations:

- **Time complexity:** O(n^3).
- **Space complexity:** O(n^2).
- Floating-point calculations may introduce significant numerical errors.
- The algorithm uses n coefficients even when the actual polynomial degree is much lower.
- Exact interpolation does not guarantee accurate recovery of the underlying relationship.

### 2. What We Want to Improve

**Our main goal is to develop a more computationally efficient polynomial recovery algorithm.**

For example, given 1,000 points generated by f(x)=2x+1, our current algorithm can theoretically recover the correct coefficients, but it requires constructing and solving a linear system with a 1000 * 1000 matrix.

We want to obtain the same result with significantly lower computational costs.

To achieve this, we plan to:

- Determine the required polynomial degree without constructing the full system in advance.
- Avoid n * n times matrices when they are unnecessary.
- Reduce time and space complexity.
- Improve numerical stability.
- Mathematically prove the correctness of the new algorithm.

### 3. Handling Noisy Data

Initially, we focus on recovering polynomial relationships from exact observations.

Later, we want to extend the algorithm to handle data containing measurement errors and random noise.

Instead of necessarily passing through every observed point, the algorithm should aim to recover the underlying polynomial relationship.

### 4. Benchmarking and Research

We want to compare future algorithms with the initial version of Polynom Hunter and existing methods.

We plan to evaluate:

- Execution time.
- Memory usage.
- Accuracy of recovered coefficients.
- Prediction accuracy on unseen data.
- Strengths and limitations of different approaches.

**Ultimate Goal:** Develop a mathematically justified and computationally efficient algorithm for recovering polynomial relationships from numerical observations.
